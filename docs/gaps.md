# Gaps

Last updated 2026-10-20 · Change: M5.8h1 (point clouds: the reader).

What the C++ fork does not do yet that CadCraft 0.5 does, ranked by how much it matters.

| Rank | Gap | Since | Notes |
|---|---|---|---|
| 1 | The apps are not ported yet (M3 onward) | 2026-10-16 | See docs/roadmap.md |
| 2 | DWG code pages other than Windows-1252 decode as Windows-1252 (the JS uses TextDecoder for 26 of them) | 2026-10-16 | No corpus file uses one; table generation from the WHATWG encodings is the fix |
| 3 | `read_dwg` has no strict mode (the JS `strict: true` throws on the first damaged object) | 2026-10-16 | Not used by the apps |
| 4 | Out-of-process import on Windows (job object, restricted token) and macOS (sandbox profile): the helper and its client are Linux-only so far; other platforms read in-process | 2026-10-16 | M3 builds the desktop app on Windows and macOS |
| 5 | Hostile input only: where the JS reader goes on with a NaN object size (`readMS` gives `0 * 2**shift` = NaN past shift 1024; `p + NaN > len` is false), the C++ refuses the object; a damaged-object note is worded differently. The DWG reader still calls `std::atan2` (1-ulp differences, within tolerance) | 2026-10-17 | Port V8's tan when a parity difference asks for it |
| 13 | Constraints and parameters (M5.8e): the document keeps them, resolves a file's CADCRAFT_PARAMETRIC payload, solves after every edit and refuses an edit they cannot follow, writes them into a saved DWG or DXF and keeps them through MIRROR, TRIM and copy and paste (M5.8f); SWBOUT and SolidWorks sketch exports are ported (M5.8g2; an export whose globals list holds a null opens here where 0.5 throws); the viewer draws constraint bars and dimensional constraints and has the Parameters panel (M5.8g), its glyphs drawn as lines (the UI font has no ⊥ ∥ ◎); its 3D model (libs/m3d) takes a file's 3D faces as loose faces but does not read CadCraft's own copy back (CADCRAFT_3D): a CadCraft-saved 3D model comes in as its faces. | 14 | The DWG writer starts every write from the loaded class table. The JS writer keeps the classes of custom objects (`RAW:<name>`) it met in earlier writes of the same page session, so a second save of another drawing in one JS session can name such a class as the first drawing did; the parity harness resets the JS table before each write (one save = one fresh write) | 2026-10-17 | Kept: a fresh table per write is what a single save does |
| 15 | DWG save: a dynamic block whose visibility states were edited (dyn-blocks.js editedVisibility, the block editor) is saved plain — the fork has no block editor yet, so no drawing it opens has such a block | 2026-10-18 | With the block editor |
