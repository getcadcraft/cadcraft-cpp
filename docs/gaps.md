# Gaps

Last updated 2026-10-18 · Change: DWG save (M4.4): sin/cos now V8's; the save's gaps (constraints, CadCraft's own 3D model, edited visibility states).

What the C++ fork does not do yet that CadCraft 0.5 does, ranked by how much it matters.

| Rank | Gap | Since | Notes |
|---|---|---|---|
| 1 | The apps are not ported yet (M3 onward) | 2026-10-16 | See docs/roadmap.md |
| 2 | DWG code pages other than Windows-1252 decode as Windows-1252 (the JS uses TextDecoder for 26 of them) | 2026-10-16 | No corpus file uses one; table generation from the WHATWG encodings is the fix |
| 3 | `read_dwg` has no strict mode (the JS `strict: true` throws on the first damaged object) | 2026-10-16 | Not used by the apps |
| 4 | Out-of-process import on Windows (job object, restricted token) and macOS (sandbox profile): the helper and its client are Linux-only so far; other platforms read in-process | 2026-10-16 | M3 builds the desktop app on Windows and macOS |
| 5 | Hostile input only: where the JS reader goes on with a NaN object size (`readMS` gives `0 * 2**shift` = NaN past shift 1024; `p + NaN > len` is false), the C++ refuses the object; a damaged-object note is worded differently. Seen on fuzz input `fuzz/corpus/dwg/regress-c0449ba28405`, never on the corpus | 2026-10-16 | Arguably a JS bug (a 0.6 fix for the owner to decide); copying NaN-bounded reads would be unsafe |
| 6 | DXF: no binary DXF (the JS refuses it too, with the same words) | 2026-10-16 | Same as 0.5 |
| 7 | Hostile input only, draw lists: where the JS compiler would run out of memory or time (a MINSERT of 10⁹ cells, a block nesting that multiplies), or throw (a spline whose degree its control points cannot carry, a dimension block that contains itself), the C++ stops at its caps (`CompileOptions::max_coords`, `max_visits`, depth 200) and marks the drawing truncated, or draws the control polygon | 2026-10-16 | `tools/parity/compile.mjs --isolate` counts "JS out of memory" separately; regressions in fuzz/corpus/compile |
| 8 | `localeCompare` (layer order) is measured for ASCII and every Windows-1252 character (tools/gen/js-collation.mjs); other scripts sort by code point after Latin, where ICU interleaves scripts and applies compatibility mappings. `toLowerCase`'s final-sigma rule is not applied | 2026-10-16 | Only the order of the layer list; no corpus file has such names |
| 9 | The 2D view: thick (print view) lines have butt ends and no round joins; text has no kerning (FreeType advances only, HarfBuzz later); raster images show their frame only (no image decoding until wuffs); fills draw one stencil pass each (many hatches = many draws: measure before batching) | 2026-10-16 | dwg-view.js draws joins round and the browser kerns |
| 10 | Linux file dialogs need zenity (SDL3 is built without D-Bus: its dbus/ibus features pull in LGPL code) and there is no IME on Linux yet; Windows has no D3D12 backend (DXC is NCSA-licensed): D3D11 and Vulkan | 2026-10-16 | Licence allowlist; drop a file or pass it on the command line |
| 11 | Hostile input only, import: a MINSERT's copies stop at 100,000 (`ImportLimits::minsert_copies`); the JS importDwg makes rows × columns objects and runs out of memory first | 2026-10-17 | Never on the corpus |
| 12 | `exp`, `log`, `tan`, `pow` are the C library's (sin, cos, atan, atan2, hypot are V8's since M4.4). Within every parity tolerance; the save calls `tan` once (the OPEN30 arrowhead) and `pow` only in comparisons. The DWG reader still calls `std::atan2` (1-ulp differences, within tolerance) | 2026-10-17 | Port V8's tan when a parity difference asks for it |
| 13 | The document (libs/doc) does not resolve constraints and parameters yet (gcons.js, params.js: a file's CADCRAFT_PARAMETRIC payload is kept as text), so **a DWG or DXF saved by the fork has no constraints** (the JS writes them back as CADCRAFT_PARAMETRIC); its 3D model (libs/m3d) takes a file's 3D faces as loose faces but does not read CadCraft's own copy back (CADCRAFT_3D): a CadCraft-saved 3D model comes in as its faces. No Studio Live hook, no add-on edit hooks | 2026-10-17 | No corpus file has either; constraints with the commands (M4.6), the 3D model with ModelCraft (M5) |
| 14 | The DWG writer starts every write from the loaded class table. The JS writer keeps the classes of custom objects (`RAW:<name>`) it met in earlier writes of the same page session, so a second save of another drawing in one JS session can name such a class as the first drawing did; the parity harness resets the JS table before each write (one save = one fresh write) | 2026-10-17 | Kept: a fresh table per write is what a single save does |
| 15 | DWG save: a dynamic block whose visibility states were edited (dyn-blocks.js editedVisibility, the block editor) is saved plain — the fork has no block editor yet, so no drawing it opens has such a block | 2026-10-18 | With the block editor |
| known issue | Screen readers: Dear ImGui has no accessibility tree | 2026-10-15 | Owner, 2026-10-15: known issue, skipped for now. Never claim screen-reader support. |
